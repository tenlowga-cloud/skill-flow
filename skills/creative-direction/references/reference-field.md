# Reference field and generated exploration

Moved out of SKILL.md.

## Build the reference field

Everything gathered is research. File it in the owner's notes (where `PROFILE.md` says they live), in a folder per project. Label it, tag it as research, link it to the owning project, and date the sources. Read that folder first so an earlier sweep is reused.

The owner's supplied examples come first. Open each one. Record what it gives and what must not transfer.

For material new work, widen the evidence before locking a direction. Use every search and fetch tool that helps, in parallel:

1. Search the images and brand assets where `PROFILE.md` says they live, by project, brand, topic, audience and visual role. Open only the relevant safe originals. Personal, client, case and ambiguous private images are not inspiration.
2. Search the topic on the live web. Study relevant large companies and category leaders for scale, trust, information, interaction, campaign or brand behavior.
3. Search adjacent industries and at least one deliberately distant field with a form, ritual or mechanic that transfers.
4. Run image search for visual and graphic work. Go past websites: campaigns, editorial systems, type, photography, packaging, signage, objects, spaces, film, games, data graphics, art direction.
5. Open the real source behind a result when its full system, provenance or rights matter.

The owner's image library and the big-company set are pools, not quotas. Use a task-shaped set where each source adds something different. Do not drown judgment in thousands of files or open 500 sites as a ritual.

Record each selected source: exact path or link, observed facts, useful contribution, non-transferable element, unexpected connector, rights status.

## Connector questions

- What is the real human tension or change?
- What could this be if it did not have to look or sound like its category?
- Which other field solved the same human problem in a different form?
- What object, place, ritual, natural system, story shape, game mechanic, publication or data relationship could carry the idea?

## Copy and story

- Truth controls the image. Never invent a fact, person, quote, number, event or pain point for color.
- One strong analogy beats a pile of clever lines.
- Vary rhythm. Paint the picture, then make the next action obvious.

## Visual defaults to reject

Generic sans stacks, centered template heroes, interchangeable bento cards, stock-photo poses, automatic dark luxury, gradients, glass, glow and model-favorite effects. A common typeface or familiar component is fine as a deliberate functional choice the brief supports. Novelty is not effects: a distinctive information structure, type system, image treatment, story sequence, physical metaphor or interaction can carry more originality than a shader.

## Generated exploration

Use generated comps when they reveal a visual or story choice before code or production hardens it.

- Use the image tool in `TOOLS.md`. Check its current official guidance for model and size options before you rely on memory.
- Give every input image an explicit role. Carry the full intent and reference list into the prompt.
- Generate truly different worlds, not variants of one model habit.
- Save project-bound outputs with their prompt and reference sidecar.
- Inspect for generic composition, fake detail, text errors, cultural mistakes, brand drift and rights issues.

For motion or video the image tool can't make, use another tool in `TOOLS.md` only when it is live and the job has the credit spend and commercial-use rights. Never pretend a tool is installed.
